# Plan setup and editing implementation evidence

Status: functional and undesigned. Work is in the isolated plan-and-session-launch checkout. This document records implementation and scoped verification; it does not claim a production deployment, full browser-suite pass, or design approval.

## Shipped in this change

- Six-step learning-plan setup: goal/starting note and natural-language date purpose; visible material upload/read/result states; an editable “What YOVA understood” page; availability; optional placement offer; grouped plan preview. Placement does not start until the learner chooses it. A no-date goal skips the placement offer.
- Understanding corrections are local until Continue. The submitted correction set contains authorized material IDs/classification overrides and an ordered list of topic IDs, their material assignments, learner-covered declarations, and bounded added topic titles. The server helper rejects unknown materials, duplicate IDs/titles, invalid ordering, dangling prerequisites, and attempted edits of existing titles. “Covered” remains an unchecked learner declaration, separate from placement evidence. Mixed material classification is preserved unless explicitly changed.
- The parent-owned generation endpoint verifies signed map authority and rehydrates authorized uploads. The UI resends normalized accepted corrections during later placement/generation so upload hydration cannot silently revert a learner's material classification. Failed reads or corrections retain the local choices and offer retry or skip.
- Partial placement scoring accepts only a valid answered prefix of the signed challenge. Unanswered questions do not become scored gaps. Partial evidence receives a signed receipt; the challenge remains single-use and idempotent under its existing authority rules.
- Grouped topic plans show all work, including practice placeholders; total/completed counts; next block; topic collapse; actual fired personalization reasons and constraints; material and editing entry points; per-block method choices; and supported date moves in the plan's timezone. Q10's collapsed queue shows the next topic with remaining topics expandable.
- Plan editing supports existing/new topic order, removal, one new topic, deadline, and availability windows. The new topic can be dragged or moved with arrow buttons before apply. A bounded `before_topic_id` addition to the existing signed delta adapter makes first-position insertion possible; the anchor must belong to the accepted map and cannot be combined with `after_topic_id`. Structural changes continue through the existing review/apply pipeline.
- Draft mark-covered and method changes apply through the existing signed preview/apply adapter, displaying its receipt and existing Undo behavior. Standalone v2 material attachments use the same pipeline immediately; whole-plan attachment emits one authorized attachment operation per active topic, limited by the existing 40-operation bound. Multiple structural edits still use preview/confirmation. No Undo implementation was changed.
- Calendar Add opens the native event composer. Plan setup's alternative event link uses parent-owned navigation. Home's plan entry and grouped active-plan integration are parent-owned.

## Regressions found while checking integration

The living-plan route suite exposed two real v2 boundary regressions. A valid draft with more than 28 blocks produced a 503 because the revision proposal schema retained the legacy limit. The schema now accepts the v2 runtime bound (400) while preserving the legacy 28-block revision bound; draft generation remains bounded separately. A duration control belonging to an excluded operation also blocked an unrelated accepted operation; the v2 blocker now inspects accepted edits only.

The previous tests assumed every current fixture was a legacy fixed-duration plan. The shared fixture now generates v2 topic plans. Existing deadline refusal, fixed-duration editing and source-budget compatibility are therefore tested using explicit legacy plans. Separate v2 tests prove full-queue preview above 28 blocks and rejection of unsupported duration shortening. The excluded-control test compares against a control-free accepted revision, rather than assuming practice always takes less time than learning. The sibling planner implementation restores the legacy source budget and refreshes revision plan metadata; this agent wires that metadata helper into revision construction.
